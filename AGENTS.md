# Команды

- запустить локальный бэкенд: `go run cmd/main.go`
- запустить базу данных перед стартом бэкенда: `docker compose up -d`

# Соглашения

- продакшен опубликован на VDS на домене again.trixy.space
- комментарии в коде не пиши
- если схема базы данных меняется, то пиши в одной миграции
- используй возможности Go 1.27 и более ранних версий
- проект студенческий, поэтому не пиши тесты
- для коммитов используй стандарт Conventional Commits
- сообщение коммита должно содержать только короткий заголовок в одну строку, без описания и без трейлеров
- если коммит относится к задаче, указывай её ключ в скобках в конце заголовка: `refactor: delete mocks (RSP-12)`
- код пиши в мастере, ответвляйся только когда пользователь явно об этом просит
- перед коммитом спрашивай пользователя, устраивает ли его название для коммита
- соблюдай стилистику написания кода как в файлах рядом с тем, который ты редактируешь
- сообщения ошибок на бэкенде пиши на английском языке, пользовательские переводы делай на фронтенде по ключам ошибок
- README.md сам не меняй, инициативу изменить не проявляй, только когда явно попросили
- SQL-запросы и их фрагменты пиши в строках с двойными кавычками, не используй обратные кавычки
- в SQL-вызовах переноси контекст, SQL и параметры на отдельные строки, то есть делай по аналогии как сейчас
